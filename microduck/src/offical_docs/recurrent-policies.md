# 循环ONNX策略
运行时支持前馈策略，以及由 mjlab/rsl_rl 导出的显式状态LSTM模型。两类模型均使用现有的61维观测值，以50Hz频率输出相同的14个原始关节动作。**观测归一化必须嵌入到导出模型内部**。训练用的评价网络（critic）不会部署，本方案不新增传感器，也不额外增加动作滤波。

## 模型契约
所有张量均为float32类型。输入、输出按名称匹配，与顺序无关。

|模型|输入|输出|
| ---- | ---- | ---- |
|前馈网络|obs [1, 61]|单个输出 [1, 14]（原有输出名称仍兼容）|
|LSTM|obs [1, 61]，h_in [层数, 1, 隐层维度]，c_in [层数, 1, 隐层维度]|actions [1, 14]，h_out [层数, 1, 隐层维度]，c_out [层数, 1, 隐层维度]|

批次维度可使用符号维度；推理时始终只针对单台机器人。层数与隐层宽度必须为正的静态数值，且四个状态张量的该参数保持一致。单个状态张量元素上限为1,048,576。
若出现不支持的张量名称、秩、数据类型、维度，或存在多余张量，模型加载直接失败。预热阶段同样会拒绝非法或非有限值输出。GRU及其他循环网络导出签名暂未实现。

发布循环策略时，配置 `model_api: 2`，旧版本守护进程会在安装前拒绝加载。当前守护进程同时兼容原有API 1的前馈模型。清单规范、观测维度、动作维度均无改动。

## 内存生命周期
每个已加载策略拥有预分配的隐状态张量与细胞状态张量。每次推理成功后，新状态会拷贝至这两片缓冲区。推理失败则清空内存；非有限值输出会在状态提交前直接拒绝。预热产生的状态会被丢弃。

在以下场景，内存从零初始化：首次激活、切换网络（切回也包含在内）、手动禁用、暂停/摔倒恢复后的控制器重置、链式技能重启。短暂传感器断连沿用现有的恢复宽限期。**在同一网络运行中变更指令，会保留原有内存状态**。

替换未激活插槽内的模型时，**仅当新旧ONNX文件SHA-256摘要一致，才保留当前活跃网络的内存**。即使文件路径不变，若活跃模型文件发生变更，状态也会从头初始化。
请使用自包含的ONNX导出包来保证该特性：外部引用权重文件不计入ONNX文件摘要。手动执行控制器重置，会清空全部插槽状态。

原有的动作缩放与可选运行时过滤器保持原有配置。如果策略训练阶段未启用动作滤波，则部署调参时需要关闭对应过滤器；引入循环结构并不会让不匹配的滤波配置变为有效。

## 离线回放与开发板时序测试
示例使用正式版Rust推理链路，不会打开电机总线：
```bash
export ORT_DYLIB_PATH=/path/to/libonnxruntime.so
cargo run --release -p duck-control --example policy-rehearsal -- policy.onnx > rehearsal.json
```
该程序会先预热Actor网络、清空状态，然后在标准重力、零指令、带前一动作反馈的条件下执行1000次推理。输出JSON包含p50/p95/p99/最大延迟、超过20ms的推理次数，以及动作序列。
**必须在Radxa开发板上运行该示例，获取板上真实时序；开发主机测得的延迟不能作为机器人的时序预算。**
该时序统计不含传感器读取、电机写入与调度延迟。

如需和PyTorch或Python版ONNX Runtime做多步确定性对比，传入JSON记录数组作为第二个参数：
```json
[{"obs": ["替换为恰好61个数值"], "reset": true}]
```
每条记录提供完整观测（包含上一轮动作）。在Episode边界设置`reset:true`。对比相同观测与重置条件下输出的动作序列。该操作用于校验推理与内存处理逻辑，**不验证仿真到真机的迁移效果**。请通过训练仓库的归一化导出脚本导出训练检查点。

## 测试命令
```bash
cargo test -p duck-control
# 需要 ONNX Runtime >=1.23
cargo test -p duck-control --test recurrent_policy -- --ignored
cargo test -p robotd recurrent_memory_resets_with_controller_feedback -- --ignored
```

仓库内附带小型测试用例，使用原生ONNX LSTM算子。覆盖内存连续性、状态重置、策略切换、降级选择、预热、热切换、动态批次维度、非法契约、非有限状态等场景。
可在安装onnx与numpy的环境中，执行下面脚本重新生成测试用例：
```bash
python duck-control/tests/fixtures/generate.py
```

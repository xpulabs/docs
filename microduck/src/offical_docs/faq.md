# 常见问题（FAQ）
本部分收录的场景：你希望 Microduck 实现出厂默认不支持的功能。设计文档讲解底层机制；本文告诉你该选用哪个组件。

## 我想运行开发板承载不了的大模型
把模型放到其他设备上运行，再向它传输摄像头画面。这款开发板是 Radxa Zero 3，板载 NPU 仅能运行小型检测器，更大规模的模型必须放到机器人外部。**Hugging Face Space 付费硬件方案**是开发量最小的选择：自带GPU选项、机器人可共用的账号体系，以及可直接访问的URL。

推荐使用 WebRTC。机器人通过 WebRTC 会话推送 H.264 码流，你的 Space 服务接收码流；由中继服务（rendezvous）完成两端互相发现，双方无需预先知道对方地址。示例工程见 `spaces/vision-demo/`。

```
你的Space ──登录、列出机器人──► 中继服务  ◄──注册──  Microduck机器人
你的Space ◄═══════════ WebRTC传输H.264音视频+控制通道 ════════════►  Microduck机器人
```

选用 WebRTC 自带三项能力，这也是它作为默认方案的原因：
1. 媒体流通过 DTLS-SRTP 做端到端加密；
2. 控制通道复用同一会话，可同时查看画面并遥控机器人；
3. 支持反向通道，后续可按需增加音频或第二路视频流。

## 部署在数据中心可以吗？我的Space处在不受我管控的NAT后面
可以。家用路由器后的机器人与数据中心NAT内的容器通常无法直接打洞建立连接。此时机器人会提供中继候选地址：使用自身账号令牌生成短期有效的 Cloudflare 凭证；接收端可直接使用该凭证，无需自己持有密钥。原理见 `remote-access-design.md` 第6节。

有两个注意事项，避免踩坑：
- 中继会消耗机器人所有者的带宽，Hugging Face免费账号每月配额10GB。持续720p码流大约每小时消耗1GB，全天不间断推流会快速耗尽配额。ICE协议会优先尝试直连，仅在直连失败时启用中继；但家用网络连数据中心的场景，经常需要走中继。
- 浏览器作为接收端，若无独立IPv4地址，则需要单独的中继凭证；Python程序接收端不需要。第6节有详细说明。

## 接收端是程序，需要7×24小时持续拉流，有没有更省成本的方案？
有一个备选方案（属于降级方案，并非主推设计）：`media.stream`。由机器人主动发起WebSocket连接，向外推送图像帧。

```
你的Space ──media.stream {url: "wss://…/frames"}──► 中继服务 ──► Microduck机器人
Microduck机器人 ══════════ 图像帧，出站WebSocket，直连 ══════════════► 你的Space
```

这个方案**不占用中继带宽**，因为是机器人主动向外建立连接，不需要端口打洞。
同时满足下面全部3个条件再选用：接收端是程序而非人；长时间推流，中继流量计费会造成成本压力；只需要图像帧，不需要其他通道。

选择这个方案需要舍弃WebRTC的能力，因此不作为默认方案：
1. **完全没有反向通道**：无法向机器人回传任何数据，没有音频、第二路视频、遥控回路；
2. **无内置控制通道**：如果要遥控机器人，需要单独通过中继服务发起JSON-RPC调用（参考 `spaces/shared/wire.py`）；
3. 加密使用TLS，而非DTLS-SRTP；加密在你的服务端终止，不是端到端对等节点加密。

机器人会先发送一条文本握手消息，描述码流信息：`frames.encoding` 为 h264 或 jpeg。**请解析这条握手消息，不要靠原始字节猜测编码**。参考接收端代码：`spaces/vision-demo/receiver.py`，`decoder_for` 是编码分支处理逻辑。

## Space如何发现机器人？如何防止其他人访问我的机器人？
依靠账号鉴权。机器人携带自身Hugging Face令牌在中继服务注册；你的Space通过hf_oauth完成访客登录。中继服务只会展示该账号名下绑定的机器人。机器人端无需额外配置，也不依赖机器人侧的访问网关。`remote-access-design.md` 第7节解释该方案的安全性依据。

`spaces/shared/rendezvous.py` 是设备列表查询接口：`ducks(token)` 会返回该账号可访问的所有机器人。

## 没有实体机器人，可以做测试吗？
`scripts/duck-sim` 在MuJoCo物理仿真环境上运行真实守护进程（文档见 `robot/simulation.md`）。仿真实例会像真实开发板一样在中继服务注册，并标记为仿真设备。Space访问仿真机器人的方式，和访问真实机器人完全一致。

### 术语简释
- rendezvous：中继/信令协商服务
- NAT：网络地址转换
- hole-punch：NAT打洞
- ICE：交互式连接建立（WebRTC网络探测）
- DTLS-SRTP：WebRTC端到端加密协议
- WebSocket：长连接双向通信协议
- JSON-RPC：远程过程调用协议

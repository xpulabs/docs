自主行为栈——继承内容与待落地构想

“大脑模块”是对等审计（§03）中最大的未跟踪缺口：运行时的 autonomous.rs 在守护进程中完全不存在，也尚无对应的设计文档。本文档作为汇总草稿，列出移植工作需要覆盖的内容，以及来自特雷门琴/合唱项目（2026-08）的构想。这些构想应当作为行为落地到本栈中，而非继续做成零散的临时模式。

从运行时移植（审计 §03）

一套16状态状态机：安静待命、环顾四周、漫游、原地转向、急速乱窜、受惊、伸懒腰、抖毛、理毛、打喷嚏、跳舞、地面捡拾、小憩、玩球、被抚摸、被抱起。基于以下模块构建：

  • 能量/情绪模型，用于驱动状态切换
  • 漫游行为所用的新奇网格探索记忆
  • 带时效门控的飞行时间（ToF）避障
  • 基于对比度的受惊触发；声音响应（区分噪声与人声），附带自身音频/自身运动门控
  • 玩球（靠近/对准/踢球）、小憩周期、抚摸交互响应
  • 进程内游戏手柄↔自主模式切换（长按方向右键2秒），--autonomous-max-speed 参数

它所需的输入源目前都已在守护进程中就绪：环境声音事件（第2步——已记录，暂无消费方）、深度帧（第3步）、主干帧中经过分类的障碍物点（第5步），以及语音标签（第2步，“就绪，等待大脑模块接入”）。被抱起状态依赖拾取检测，该功能已被弃用——需要决定是恢复该功能还是直接移除这个状态。

大脑模块新增免费输入（2026-08项目成果）

特雷门琴/合唱项目开发的、旧版运行时大脑模块原本不具备的能力：

  • 通过稳定ID识别附近机器鸭：合唱信标（ChoraleBeacon），可抵御BLE地址轮换（参见文档/../内存模块：永远不要把地址作为主键）
  • 无需时钟同步的共享节拍（sounds::chorale::beat）：机器鸭之间误差±20毫秒
  • 每个广播包的RSSI信号强度：可直接获取粗略距离（近/远/正在靠近）
  • 扩展广播载荷中约245字节可用空闲空间
  • 实时合成语音流（sounds::Stream）：运行时可调整音高/音量/元音，不再只能使用预存wav音频
  • 通过ToF获取手部距离（kinematics::hand::Tracker 手部追踪器）

行为构想（大致按“代码行数/趣味性”排序）

社交类（BLE邻近感知——新领域）

  • 识别与问候：持久保存遇到过的机器鸭ID列表；对陌生个体发出问候，对老友使用更柔和的音效；当老友的信标信号消失时发出轻啄/叹息音效。友好度由相遇次数决定，随时间改变问候方式。属于记忆功能，无需同步。
  • 孤单/安心状态：单独一只机器鸭会时不时鸣叫；有同伴时则不会鸣叫。这是情绪模型的输入项，并非独立状态。
  • 靠近时的兴奋感：已知ID对应的RSSI信号持续上升 → 表现出期待的动作。
  • 马可波罗：一只机器鸭躲藏，另一只通过信标RSSI变强加快嘎嘎声来引导你。
  • 跟队跟随：依靠RSSI维持间距，ToF负责识别正前方的机器鸭。
  • 喝彩/社交反馈：一只机器鸭演奏一段连奏，附近机器鸭做出响应。
  • 传声筒：消息通过空闲载荷在机器鸭之间逐鸭传递，内容可在传递中发生变化。
  • 投票机制：偏好信息写入信标载荷；多数派决定群体下一个行为。

节拍同步动作（复用同步成果，无需扬声器参与）

  • 群体点头/摇摆：所有机器鸭跟随共享节拍同步动作；视觉同步允许约50ms误差（音频同步要求20ms）。小节重拍时保持群体统一姿态；可排成康加舞队列。
  • 跳舞（已有运行时状态）：存在同伴时切换为同步集体舞。

音乐类（合唱之外的音乐玩法）

  • 一问一答：对唱乐句；乐句之间的间隔可以掩盖同步误差，实现难度低于合唱，也更贴合机器鸭的风格。
  • 轮唱：同一旋律，刻意设置多小节偏移；偏移量用来抵消同步误差。
  • 分工演奏：持续低音 + 节奏啄击声 + 主旋律。小型扬声器更适合表现音色层次，而非复杂和声。

机器鸭检测器（摄像头+NPU）——待实现，依赖mediad服务

一个轻量单类别检测器，专门识别本项目的机器鸭：提供精确方位，用于注视与跟随，这是ToF和BLE都无法做到的。RK3566搭载0.8 TOPS INT8 NPU（rknpu2 / rknn-toolkit2）；输入320分辨率的YOLOv8n/11n类模型，推理耗时约20–40ms，帧率15–30Hz，不占用CPU。测距估算：IMX219水平视场角约62°，一只25cm的机器鸭在3米距离成像约25像素，适配室内空间尺度，也就是交互有效范围。

前置校验：板载是否存在NPU驱动？（dmesg | grep -i rknpu）——使用厂商内核的rknpu2，不是主线内核版本。同时需要 /dev/rga 硬件模块，免费完成NV12图像缩放。要求mediad服务从ISP主通路旁路输出原始NV12图像；检测器不得对MJPEG视频流做解码。

项目核心是数据，而非模型本身。机器鸭视角录像（机器人高度、机器人摄像头）由大开放词汇模型自动标注，再蒸馏得到小模型；利用Open Duck CAD模型渲染合成尾部样本；加入困难负样本（橡胶鸭、白色打印图案）。

多感知融合：视觉无法区分外观完全相同的机器鸭——摄像头提供方向，ToF提供距离，BLE信标提供身份与存在性。跟队跟随同时使用三者；“互动时互相注视”：信标确定触发时机，检测器给出目标位置，robot.look 模块完成剩余动作。

架构与tofd/宠物检测保持一致：在robotd之外独立的感知工作进程，可安全终止。在移植mediad期间修复IMX219内参占位符（审计 §04 待办项）。

移植工作要点

邻近存在、情绪状态、共享节拍都属于大脑模块的输入，不是独立于大脑之外的模式。合唱/特雷门琴当初做成独立模式，是因为当时没有大脑模块来承载；大脑模块落地后，需要把它们整合为状态/输入。（“被抚摸”之于宠物检测，就如同“歌唱”之于收到的信标信号）

合唱最终是自发事件，不是命令。robotctl chorale 只是调试台工具：当机器鸭自主运行后，多只共处时会在低概率下自发开启合唱。触发前提：存在同伴（也可叠加情绪/能量条件），触发逻辑类似急速乱窜、跳舞，不由用户手动启动。刻意降低触发概率：意外的二重唱才有趣，而不是自动点唱机。底层机制改动很小——处于空闲状态、广播信标的机器鸭本就知道附近有谁，所以“决定开唱”只是新增一条状态迁移；[chorale] accept 保留作为准入开关，控制单只机器鸭是否可以参与合唱。

合唱的许可规则可以推广：所有社交行为都采用可选加入，关闭则完全不生效（现在是[chorale] accept，未来可能统一为[social]总开关）。

识别与问候是最合适的首个落地行为：单位代码行数带来的趣味性最高，无需同步，还能验证BLE发现层——这部分硬件稳定性仍有待验证。

术语小注（机器人/嵌入式开发专有名词）

  • autonomous behavior stack：自主行为栈

  • rknpu2、rknn-toolkit2：瑞芯微NPU驱动与工具链
  • YOLOv8n/11n：轻量目标检测模型
  • NV12、MJPEG：图像编码格式
  • HFOV：水平视场角
  • intrinsics：相机内参
  • CAD：计算机辅助设计
  • distill：模型蒸馏（深度学习）
  • ad-hoc：临时、临时拼凑的
  • opt-in：选择性加入、用户主动启用
